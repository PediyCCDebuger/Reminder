# Reminder（AddinTimer 定时部分复刻版）

本分支把 `lentikr/Reminder` 改造成 **AddinTimer 2.1G 定时部分的复刻**：界面按原版截图逐屏重做，数据格式与原版 `.atk` 备份 100% 兼容，调度层按当前 Android 重写（精确闹钟 + 通知 + 全屏提醒）。应用名与主页标题统一为 `Reminder`；每个版本改了什么见 [CHANGELOG.md](CHANGELOG.md)，GitHub Release 的说明由该文件自动生成。

原版 AddinTimer 2015 年停更，只声明了 `minSdkVersion=4`、没有 `targetSdkVersion`，Android 14+ 直接拒绝安装；菜单依赖硬件 MENU 键；也不会申请 Android 12 引入的 `SCHEDULE_EXACT_ALARM`。

**首次启动**会载入原版自带的 18 条示例任务（常用 4 / 生活 5 / 纪念日 5 / 生日 4），与原版一样**默认全部未激活**，需要哪条就手动打开右侧开关；「备份恢复 → 载入原版示例任务」可随时重置。标题栏「多选」可勾选当前分类下多条任务，一次性移动到别的分类；长按菜单里也有「移动分类」（单条）和「多选模式」。

## 界面（逐屏对照原版 2.1G）

**主界面**：银灰标题栏 `Reminder`、蓝色渐变「新增任务」大按钮、深色任务列表（闹钟图标 / 名称 / `[按周] 一,二,三,四,五` / 「明天」标签 / 时间 / 绿灰色开关条）、底部「常用 / 生活 / 纪念日 / 生日」四个标签。四个标签直接对应备份里的 `base[1] = 100..103`，导入后自动归位；新建任务会落在当前标签下。

**新增任务**：只保留原版弹窗里的「**提醒管理**」一组 —— 定时提醒、快速提醒、整点报时。设备管理 / 通信管理 / 媒体管理 / 其他管理按需求不复刻。三种入口分别预置按周循环、一次性指定日期、每小时报时。

**时间设置 / 参数设置**：银灰标题栏「定时提醒」+ 两个深色 Tab 按钮 + 深灰分组标题条 + 银灰渐变下拉框（左侧固定宽度标签，右侧当前值，绝不换行挤在一起）+ 底部蓝框「✓ 确定 / ✗ 取消」。

- **常规设置**：任务名称、开始时间。点「开始时间」弹出原版样式的黑色数字弹窗：时、分两列，各自 `+` / `−`；数字框可以**直接点进去输入**（自动限位 0–23 / 0–59），`+` / `−` 的步进可选「1 分钟 / 5 分钟 / 10 分钟」，分钟进位会带到小时（11:58 +5 → 12:03）；底部「设置 / 现在 / 取消」。所有日期项（选择日期 / 开始日期 / 目标日期）同样用原版样式的「选择日期」弹窗：年、月、日三列 `+` / `−` + 可直接输入，底部「设置 / 今天 / 取消」，日期自动夹到当月天数。
- **执行策略**：执行策略（按周循环 / 指定日期 / 按天循环 / 按年月循环 / 按阴历循环 / 倒计时）+ 随模式变化的具体设置
  - 按周循环 → 选择星期
  - 指定日期 → 选择日期
  - 按天循环 → 间隔天数、开始日期
  - 按年月循环 → 选择月份、月内循环（按天计算 / 按周计算）、选择天数或「出现顺序 + 选择星期」、排除几号、排除星期几
  - 按阴历循环 → 选择阴历月（正月…腊月）、选择阴历天（初一…三十 / 最后一天）、包含闰月
  - 倒计时 → 从现在开始（否：目标日期，在目标日期的开始时间一次性提醒；是：倒计时分钟，从保存时刻起 N 分钟后一次性提醒，锚点存 `base[6]`）
- **时循环设置**：时循环（不启用 / 启用）；启用后出现「每几分钟」「结束时间」
- **其他设置**：执行前通知、桌面小部件
- **参数设置**：严格按原版截图显示 **18 行**（字段索引来自 `GSW/AddinTimer/ad.a(String)`）
  - 通知设置：播报时间、铃声类型、选择路径、重复次数、音量大小、渐响模式、强制外放、振动类型
  - 贪睡设置：预设时间、自动贪睡
  - 界面设置：屏幕模式、翻转感应、界面样式、算术题解锁、电源键按下、手动贪睡、终止确认

**系统菜单**（点标题栏右侧 `≡`）：新增任务、系统设置、管理标签、备份恢复、分享好友、检查更新、建议反馈、关于软件。系统设置页与「管理标签」「备份恢复」对话框均按原版文案与布局复刻；「服务状态」一行进入新系统所需的权限自检。

所有下拉选项的中文文案、顺序与数量均取自原版 `resources.arsc` 的 array 资源，不是凭印象写的。

## 数据格式（100% 兼容 `.atk`）

`.atk` 就是 SQLite 数据库原样拷贝，核心表 `timer(id, param)`。本工程直接沿用这个表结构：

```
<KIND>|<14 个基础字段，用 $ 分隔>|<动作参数，用 | 分隔>
```

- 基础字段第 5 项是 `ko.a()` 生成的 **28 项 `#` 分隔规则串**；第 2/3/4 项是名称/时/分；第 10 项是激活标志；第 8/11/13 项分别是执行前通知/桌面小部件/执行后动作；第 2 项（索引 1）是分类页 100..103。
- `ALARM` 有 **27 个动作参数**，顺序来自 `ad.a(String)` 反汇编；例如 `[0]` 提醒备注、`[7]` 铃声路径、`[23]` 播报内容多选、`[24]` 手动贪睡。
- 六种模式编号：`0=按周 1=指定日期 2=按天 3=按年月 4=按阴历 5=倒计时`。月份/日期**列表是 0-based**，DatePicker 的年月日字段是 1-based。
- 农历表 1900–2099 内置离线数据，与 `lunardate` 交叉验证 398 个样本 0 差异。

已用 `20261109182226.atk`（18 条：ALARM 14 / FM 2 / SCENE 2）做无损往返验证：**18 条 0 差异**；这 18 条同时也是首次启动内置的示例任务（仅去掉个人铃声路径，并按原版把激活标志复位为 0）。**导入自己的 `.atk` 时逐字节保留 `param`**：激活标志（有开有关）和分类（含「常用 / 生活对调」这种自定义调整）都完全按备份还原，不会自动启用任何一条。批量移动分类只改写 `base[1]`，其余字节不动。

## 使用

1. 安装后打开 App，会先请求 Android 13+ 的通知权限；再点标题栏右侧 `≡` →「系统设置」→「服务状态」，逐项开启：精确闹钟（闹钟和提醒）、通知权限、忽略电池优化、全屏通知、悬浮窗（后台弹出界面）。另外到系统「应用管理」开启「允许自动启动 / 允许后台运行」，一加 ColorOS 上这一步是漏响的头号原因。
2. 状态栏会出现小闹钟图标（走 `IMPORTANCE_DEFAULT` 的静音渠道，LOW/MIN 渠道系统不绘制状态栏图标），下拉通知里常驻显示**最近的一次任务**，格式如 `早起床 - [明天 06:30]`；点击可打开主界面。系统设置里「通知栏图标 = 不显示」可隐藏它。
3. `≡` →「备份恢复」→「恢复环境」选 `.atk` 文件 → 选「替换当前所有定时器」或「追加到当前列表」。**已解除原版未注册版的激活数量上限**，但导入时每条任务的激活状态与所属分类都按备份原样保留，需要启用的请手动打开右侧开关。
4. 「备份环境」会写出一份标准 `.atk`，原版 AddinTimer 也能打开；「载入原版示例任务」可随时恢复 18 条内置示例。
5. 长按单条任务可「测试执行」验证提醒链路，或「执行规划」查看未来 10 次触发时间。若真机出现闪退，「关于软件」会显示最近一次崩溃日志，便于无 root 定位。
6. **到点不响时先看「触发日志」**：`≡` →「系统设置」→「服务状态」→「权限自检」→「触发日志」，最近 200 条记录包含闹钟触发、前台服务各级结果、播铃起播与异常、执行界面是否被拦。没有记录 = 系统没唤醒闹钟；有记录但没有「起播」= 音频/铃声被拦。

调度用 `AlarmManager.setAlarmClock()` + 高优先级通知渠道 + 前台服务保活（锁屏也能响）+ 全屏提醒页 + 贪睡/终止操作，开机、时间变更、应用更新后自动重排；执行记录写入原版同款 `actlog` 表，供「查看日志」使用。

闹钟的触发入口是**前台服务**而不是广播：精确闹钟的 `PendingIntent` 由 `getForegroundService()` 构造，由系统直接拉起 `AtkAlarmService`（`mediaPlayback|specialUse`），进入前台后持唤醒锁、按任务设置播铃并打开执行界面。这样做的原因是后台广播在国产 ROM 上可能被延迟投递给被冻结的应用，表现就是「到点什么都不发生，解锁点通知才响」。前台服务进入前台失败时按类型逐级回退，仍然照常播铃并打开执行界面。

铃声、音量、渐响、振动都来自任务自身的参数：`act[6]` 铃声类型、`act[7]` 选择路径、`act[9]` 音量大小、`act[10]` 渐响模式、`act[12]` 振动类型。播放使用 `MediaPlayer`（`USAGE_ALARM` + `setWakeMode(PARTIAL_WAKE_LOCK)`），渐响从目标音量的 12% 每秒抬升一次；闹钟通知渠道本身是静音的，避免渠道默认铃声在 0 秒就以最大音量盖掉渐响。

## 与原版的差异（如实说明）

- 只做**提醒**。FM / SCENE 等任务类在原版会切换飞行模式、音量等，本版只弹提醒，参数按原样读写以免数据丢失；示例中的这 4 条保持停用。
- 状态栏小图标与「最近一次任务」常驻通知已复刻；原版的 TTS 语音播报、ROOT 操作、桌面小部件、算术题解锁等交互未复刻，设置项按原版保留但只有与当前 Android 权限模型兼容的部分会实际生效。
- 原版普通版 5 个 / 增强版 10 个激活数量限制**已移除**，任意多条可同时启用。
- 铃声类型为「系统铃声」时，选「选择路径 → 系统铃声」会打开**系统铃声选择器**（`ACTION_RINGTONE_PICKER`，类型为闹钟），在 ColorOS 上就是原版那个「经典铃声 / 自然铃声 / 本地铃声 / 在线铃声」的页面；为「媒体库 / 指定音乐」时点选择路径直接列出媒体库音频；也可「从文件选择铃声…」或手动输入路径。选择路径行显示文件名。原版备份里的绝对路径在 Android 11+ 分区存储下不可读，导入后需要重新选一次。
- 模式 5「倒计时」为一次性提醒：「从现在开始=否」在目标日期的开始时间响一次；「从现在开始=是」从保存时刻起按「倒计时分钟」响一次（锚点存 `base[6]`，重启 / 重排程不重新计时）。原版的执行前等待倒计时（响铃前的等待提示）未复刻。
- 系统菜单在原版由硬件 MENU 键唤出；现代手机没有该按键，复刻版在标题栏右侧提供 `≡` 入口。

## 功能

- **倒数日与正数日**：倒数日显示“还有 N 天”，过期的一次性日期显示“已过”；正数日从开始当天算第 1 天。
- **农历**：可以直接用农历年/月/日滚轮选择日期，包括闰月。按农历重复时，闰月在没有该闰月的年份落到同名月份，三十在小月落到廿九。
- **重复周期**：每 N 天、周、月、年。下一次日期总是从原始日期推算，不会因为经过小月而漂移（例如 1 月 31 日按月重复，3 月仍是 31 日）。
- **分组与置顶**：置顶的纪念日排在最前，其余按分类分组；组内按最近的日期排序。
- **多选**：长按进入多选，可批量置顶或删除，删除后可在提示条中撤销。
- **分享与保存图片**：分享图沿用 1.x 的台历页样式，有木纹、花园、夜空三种背景，导出 1440×1920 的 PNG。保存到相册不需要存储权限。
- **外观**：跟随系统 / 浅色 / 深色；深色下可开纯黑背景；Android 12 以上可用壁纸动态取色；卡片和列表两种视图。
- **备份与恢复**：导出为带版本号的 JSON 文件，也能导入 1.x 导出的备份。
- **大屏**：平板和横屏下列表与详情并排显示。

## 构建

需要 JDK 17 和 Android SDK 37。

```bash
./gradlew assembleDebug        # 调试版
./gradlew testDebugUnitTest    # 单元测试
./gradlew assembleRelease      # 发布版（开启 R8 压缩和资源压缩）
```

包名是 `app.lentikr.reminder`，调试版会加 `.debug` 后缀，两者可以装在同一台设备上。每种构建都输出两个 APK，位于 `app/build/outputs/apk/<debug|release>/`：

- `app-arm64-v8a-*.apk`：只含 arm64 原生库，适用于现在绝大多数手机
- `app-universal-*.apk`：包含全部架构，适用于模拟器、x86 设备和旧的 32 位手机

发布签名从项目根目录的 `keystore.properties` 读取，CI 上也可以用环境变量。这个文件和 `release.jks` 都已加入 `.gitignore`，不要提交。请另外备份 `release.jks` 和密码：丢失后无法再发布能覆盖安装的更新。

```properties
storeFile=release.jks
storePassword=…
keyAlias=…
keyPassword=…
```

对应的环境变量是 `REMINDER_STORE_FILE`、`REMINDER_STORE_PASSWORD`、`REMINDER_KEY_ALIAS`、`REMINDER_KEY_PASSWORD`。没有配置签名时，`assembleRelease` 输出未签名的 APK。

## 自动构建与发布

- `.github/workflows/ci.yml`：推送到 `main` 和每个 Pull Request 都会跑单元测试、lint 和调试版构建。
- `.github/workflows/release.yml`：推送 `v*` 标签、`repository_dispatch(build-release)` 或手动运行时构建签名的发布版，创建 GitHub Release 并附上三个 ABI APK 和 `SHA256SUMS`。标签必须和 `app/build.gradle.kts` 里的 `versionName` 一致，带 `-` 的标签（如 `v2.1.0-beta1`）会标成预发布。
- `.github/workflows/build-apk.yml`：仅 `workflow_dispatch` 手动触发，构建签名 APK 并作为 artifact 上传，**不**发布 Release，避免和 release.yml 抢同一个 tag。

发布工作流需要在仓库的 Settings → Secrets and variables → Actions 里配置两个 secret（密钥别名固定为 `reminder`，key 密码与 store 密码相同，由工作流从同一个 secret 派生）：

| Secret                     | 内容                         |
| -------------------------- | ---------------------------- |
| `REMINDER_KEYSTORE_BASE64` | `release.jks` 的 base64 编码 |
| `REMINDER_STORE_PASSWORD`  | keystore / key 密码          |

## 测试

单元测试覆盖最容易出错的逻辑：

- `DayCounterTest`：天数计算、各种重复周期、月末与闰日、农历重复中的三十和闰月
- `LunarCalendarTest`：已知节日的公农历换算、全年往返换算、闰月和月份天数
- `BackupCodecTest`：备份往返、未知字段、新版本文件、损坏文件、1.x 格式导入
- `BuildSectionsTest`：置顶、分类分组和排序
- `CaptionTest`：卡片和列表下方的日期说明，包括农历、闰月和跨年的腊月
- `ReadAtMostTest`：恢复备份时的文件大小上限

## 项目结构

```
app/src/main/kotlin/com/lentikr/reminder/
├── domain/      纪念日模型、天数计算、农历封装（纯 Kotlin，可单测）
├── data/        Room、DataStore、备份、图片导出
├── di/          Hilt 模块
└── ui/
    ├── home/        列表、卡片、多选
    ├── detail/      详情、分享图
    ├── edit/        新建/编辑、日期和重复选择器
    ├── settings/    设置
    ├── navigation/  Navigation 3 路由
    ├── common/      台历卡片等共用组件
    └── theme/       配色、动态取色、纯黑主题
```
