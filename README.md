# Reminder（AddinTimer 定时部分复刻版）

本分支把 `lentikr/Reminder` 改造成 **AddinTimer 2.1G 定时部分的复刻**：界面按原版截图逐屏重做，数据格式与原版 `.atk` 备份 100% 兼容，调度层按当前 Android 重写（精确闹钟 + 通知 + 全屏提醒）。应用名与主页标题统一为 `Reminder`。

**当前版本 3.7.4（`versionCode` 51）**。仓库的 `main` 与 `master` 两个分支内容一致 —— 3.7.1 起每个版本都会同步推送，主页（默认分支 `main`）显示的源码与说明始终是最新的。每个版本改了什么见 [CHANGELOG.md](CHANGELOG.md)，GitHub Release 的说明由该文件自动生成。

原版 AddinTimer 2015 年停更，只声明了 `minSdkVersion=4`、没有 `targetSdkVersion`，Android 14+ 直接拒绝安装；菜单依赖硬件 MENU 键；也不会申请 Android 12 引入的 `SCHEDULE_EXACT_ALARM`。

**首次启动**会载入原版自带的 18 条示例任务（常用 4 / 生活 5 / 纪念日 5 / 生日 4），与原版一样**默认全部未激活**，需要哪条就手动打开右侧开关；「备份恢复 → 载入原版示例任务」可随时重置。标题栏「多选」可勾选当前分类下多条任务，一次性移动到别的分类；长按菜单里也有「移动分类」（单条）和「多选模式」。

## 界面（逐屏对照原版 2.1G）

**主界面**：银灰标题栏 `Reminder`、蓝色渐变「新增任务」大按钮、深色任务列表（闹钟图标 / 名称 / `[按周] 一,二,三,四,五` / 「明天」标签 / 时间 / 绿灰色开关条）、底部「常用 / 生活 / 纪念日 / 生日」四个标签。四个标签直接对应备份里的 `base[1] = 100..103`，导入后自动归位；新建任务会落在当前标签下。

**主界面排序**：**启用的任务永远排在前面，停用的任务排在后面**；两个分组内部都按「系统设置 → 任务排序方式」（按执行时间 / 按创建时间 / 按名称）排序，排序值相同再按任务 id 兜底，因此每次进入首页的顺序完全一致。3.7.4 起首次冷启动与从设置 / 编辑页返回共用同一个列表装配入口（`refresh()`），不再出现「刚进首页是数据库 id 原序、进一次设置才排好」的情况；「按创建时间」用 `AUTOINCREMENT` 的任务 id 作键，「按执行时间」整批共用一个时间基准并预计算排序键，保证顺序稳定。

**新增任务**：只保留原版弹窗里的「**提醒管理**」一组 —— 定时提醒、快速提醒、整点报时。设备管理 / 通信管理 / 媒体管理 / 其他管理按需求不复刻。三种入口分别预置按周循环、一次性指定日期、每小时报时。

**时间设置 / 参数设置**：银灰标题栏「定时提醒」+ 两个深色 Tab 按钮 + 深灰分组标题条 + 银灰渐变下拉框（左侧固定宽度标签，右侧当前值，绝不换行挤在一起）+ 底部蓝框「✓ 确定 / ✗ 取消」。

- **执行策略**：执行策略（按周循环 / 指定日期 / 按天循环 / 按年月循环 / 按阴历循环 / 倒计时）+ 随模式变化的具体设置
  - 按周循环 → 选择星期
  - 指定日期 → 选择日期
  - 按天循环 → 间隔天数、开始日期
  - 按年月循环 → 选择月份、月内循环（按天计算 / 按周计算）、选择天数或「出现顺序 + 选择星期」、排除几号、排除星期几
  - 按阴历循环 → 选择阴历月（正月…腊月）、选择阴历天（初一…三十 / 最后一天）、包含闰月

- **时循环设置**：时循环（不启用 / 启用）；启用后出现「每几分钟」「结束时间」
- **其他设置**：执行前通知、桌面小部件
- **参数设置**：原版截图的 18 行 +「暂停时长」+「静音时长」共 **20 行**（字段索引来自 `GSW/AddinTimer/ad.a(String)`）
  - 通知设置：播报时间、铃声类型、选择路径、重复次数、音量大小、渐响模式、强制外放、振动类型

  - 其他设置：提醒备注
  - **静音时长**（3.7.3，默认 3 分钟，可选 1/2/3/5/10/15/30 分钟）：按钮「静音」、翻转静音、滑动方式「上滑静音」后只停声音，到点会像贪睡一样**重新响铃 + 振动 + 通知 / 执行界面**；用户点贪睡或终止会立刻取消这个待重响闹钟。避免「静音后睡着就再也不响」。
  - 「暂停时长」写在扩展参数 `act[27]`、「静音时长」写在 `act[28]`；旧备份没有这两项时都按 3 分钟处理，原有 27 个字段一个不丢。
  - 原版这一屏没有「播报位置 / 声音模式 / 延迟时间 / 间隔时间 / 播报内容 / 光线感应器 / 暂停方式」等行，已从界面移除；**这些参数仍按原样读写保存**，导入与编辑都不会丢数据。
- **没有「结束与排除」分组**：原版界面没有这一组，已删除。规则默认**不设结束时间、一直循环执行**；备份里的结束日期字段原样保留，但调度层不使用它。「执行规划」里会显示未来 10 次执行时间。

**长按单条任务**：测试执行、删除条目、参考新建、执行规划、查看日志、移动分类、多选模式、60 秒后真实触发。「测试执行」会**直接进入任务执行界面**（不再只弹提示），并在状态栏同时显示「当前任务」闹钟图标与常驻图标；执行界面按任务里配置的铃声播放并振动，底部按「界面样式」显示按钮方式（静音 / 贪睡 / 终止）或滑动方式（上滑静音 / 贪睡 / 终止）。「60 秒后真实触发」走的是真实链路（精确闹钟 → 前台服务 → 响铃 → 执行界面），可锁屏验证，且不影响任务原来的排程。

**系统菜单**（点标题栏右侧 `≡`）：新增任务、系统设置、管理标签、备份恢复、分享好友、检查更新、建议反馈、关于软件。系统设置页与「管理标签」「备份恢复」对话框均按原版文案与布局复刻；「服务状态」一行进入新系统所需的权限自检。

**任务执行界面**：`AddinTimer Simplify your life` 标题、公历 / 农历 / 星期、右侧大时钟、任务名与提醒备注，底部是按「界面样式」切换的操作区。

- **按钮方式**：静音 / 贪睡 / 终止三个「圆形图标 + 文字」按钮。点「静音」只停声音与振动，**任务不终止**，界面随即去掉静音、剩下贪睡 / 终止两个按钮（外观仍是图标 + 文字）；「静音时长」到点自动重新响铃。
- **滑动方式**：两端是与按钮方式相同的「图标 + 文字」贪睡 / 终止按钮（也可直接点击），中间灰色滑块可真实左右拖动，拖过阈值松手即执行（左 = 贪睡、右 = 终止），幅度不足回弹；**上滑 = 静音**，静音后不再显示静音入口，只剩贪睡 / 终止两个选项，同样受「静音时长」保护。所有动作按钮一律图标 + 文字，不会只剩图标。
- **手动贪睡**：参数里选「选择贪睡时间」时，点 / 滑到贪睡会弹出原版深色列表（45 / 30 / 15 / 10 / 5 / 3 分钟）现场选；选「使用预设贪睡时间」则直接用「预设时间」。
- **终止确认**：参数里默认「要求确认」，点终止会弹出「警告 / 终止提醒，不再贪睡？／ 确定 · 取消」；设为「无确认」则直接终止。三个动作统一经过「算术题解锁」门控。
- **解锁即进界面**：任务执行期间（含「不点亮屏幕」模式、暂停后重响、已静音）用户主动解锁屏幕，会直接进入执行界面；解锁不会再被误判成「按电源键」而触发一次暂停。已在界面上的情况下不再重建，避免闪屏。
- **电源键按下**：灭屏立即按设置暂停 / 贪睡；只按亮锁屏而不解锁时 1.1 秒后按设置暂停。「暂停提醒」按「暂停时长」自动继续，不会终止任务。
- **翻转感应**：翻转贪睡 / 翻转静音由前台服务统一监听，不点亮屏幕时也生效；翻转静音等同界面上的「静音」，任务保留，解锁后进入只剩贪睡 / 终止两个（带文字）按钮的界面，「静音时长」到点仍会重新响铃。

所有下拉选项的中文文案、顺序与数量均取自原版 `resources.arsc` 的 array 资源，不是凭印象写的。

## 数据格式（100% 兼容旧版 `.atk`）

> **兼容性方向（3.7.3 起明确）**：本 App **100% 兼容旧版 AddinTimer 的 `.atk` 数据** —— 27 个原有动作参数逐字段读入，缺失的扩展参数（`act[27]` 暂停时长、`act[28]` 静音时长）按默认值兜底，一个原有字段都不会丢。反过来**不保证新版备份能被旧版 AddinTimer 读取**：旧版在现行 Android 上已无法正常使用，后续也不会再用，所以不再为反向兼容做妥协。单元测试 `AtkModelTest.oldAddinTimerBackupIsStillReadLosslessly()` 覆盖这一点。

`.atk` 就是 SQLite 数据库原样拷贝，核心表 `timer(id, param)`。本工程直接沿用这个表结构：

```
<KIND>|<14 个基础字段，用 $ 分隔>|<动作参数，用 | 分隔>
```

- 基础字段第 5 项是 `ko.a()` 生成的 **28 项 `#` 分隔规则串**；第 2/3/4 项是名称/时/分；第 10 项是激活标志；第 8/11/13 项分别是执行前通知/桌面小部件/执行后动作；第 2 项（索引 1）是分类页 100..103。
- `ALARM` 有 **27 个动作参数**，顺序来自 `ad.a(String)` 反汇编；例如 `[0]` 提醒备注、`[7]` 铃声路径、`[23]` 播报内容多选、`[24]` 手动贪睡。
- 六种模式编号：`0=按周 1=指定日期 2=按天 3=按年月 4=按阴历 5=倒计时`。月份/日期**列表是 0-based**，DatePicker 的年月日字段是 1-based。
- 农历表 1900–2099 内置离线数据，与 `lunardate` 交叉验证 398 个样本 0 差异。

已用 `20261109182226.atk`（18 条：ALARM 14 / FM 2 / SCENE 2）做无损往返验证：**18 条 0 差异**；这 18 条同时也是首次启动内置的示例任务（仅去掉个人铃声路径，并按原版把激活标志复位为 0）。**导入自己的 `.atk` 时逐字节保留 `param`**：激活标志（有开有关）和分类（含「常用 / 生活对调」这种自定义调整）都完全按备份还原，不会自动启用任何一条。批量移动分类只改写 `base[1]`，其余字节不动。

## 使用

1. 安装后打开 App，会先请求 Android 13+ 的通知权限；再点标题栏右侧 `≡` →「系统设置」→「服务状态」，逐项开启：精确闹钟（闹钟和提醒）、通知权限、忽略电池优化、全屏通知、悬浮窗（后台弹出界面）。另外到系统「应用管理」开启「允许自动启动 / 允许后台运行」，一加 ColorOS 上这一步是漏响的头号原因。
2. 状态栏会出现小闹钟图标（走 `IMPORTANCE_DEFAULT` 的静音渠道，LOW/MIN 渠道系统不绘制状态栏图标），下拉通知里常驻显示**最近的一次任务**，格式如 `早起床 - [明天 06:30]`；点击可打开主界面。系统设置里「通知栏图标 = 不显示」可隐藏它。
3. `≡` →「备份恢复」→「恢复环境」选 `.atk` 文件 → 选「替换当前所有定时器」或「追加到当前列表」。**已解除原版未注册版的激活数量上限**，但导入时每条任务的激活状态与所属分类都按备份原样保留，需要启用的请手动打开右侧开关。
4. 「备份环境」会写出 `.atk`；「载入原版示例任务」可随时恢复 18 条内置示例。兼容性策略见下方「数据格式」。
5. 长按单条任务可「测试执行」验证提醒链路，或「执行规划」查看未来 10 次触发时间。若真机出现闪退，「关于软件」会显示最近一次崩溃日志，便于无 root 定位。
6. **到点不响时先看「触发日志」**：`≡` →「系统设置」→「服务状态」→「权限自检」→「触发日志」，最近 200 条记录包含闹钟触发、前台服务各级结果、播铃起播与异常、执行界面是否被拦。没有记录 = 系统没唤醒闹钟；有记录但没有「起播」= 音频/铃声被拦。两个日志开关互相独立：系统设置 →「执行日志」只控制 `actlog` 执行记录（查看日志 / 保存期限 / 清空），权限自检 →「调试」只控制触发日志；关掉「执行日志」不影响排查漏响。

调度用 `AlarmManager.setAlarmClock()` + 高优先级通知渠道 + 前台服务保活（锁屏也能响）+ 全屏提醒页 + 贪睡/终止操作，开机、时间变更、应用更新后自动重排；执行记录写入原版同款 `actlog` 表，供「查看日志」使用。

闹钟的触发入口是**前台服务**而不是广播：精确闹钟的 `PendingIntent` 由 `getForegroundService()` 构造，由系统直接拉起 `AtkAlarmService`（`mediaPlayback|specialUse`），进入前台后持唤醒锁、按任务设置播铃并打开执行界面。这样做的原因是后台广播在国产 ROM 上可能被延迟投递给被冻结的应用，表现就是「到点什么都不发生，解锁点通知才响」。前台服务进入前台失败时按类型逐级回退，仍然照常播铃并打开执行界面。

铃声、音量、渐响、振动都来自任务自身的参数：`act[6]` 铃声类型、`act[7]` 选择路径、`act[9]` 音量大小、`act[10]` 渐响模式、`act[12]` 振动类型。播放使用 `MediaPlayer`（`USAGE_ALARM` + `setWakeMode(PARTIAL_WAKE_LOCK)`），渐响从目标音量的 12% 每秒抬升一次；闹钟通知渠道本身是静音的，避免渠道默认铃声在 0 秒就以最大音量盖掉渐响。

## 与原版的差异（如实说明）

- 只做**提醒**。FM / SCENE 等任务类在原版会切换飞行模式、音量等，本版只弹提醒，参数按原样读写以免数据丢失；示例中的这 4 条保持停用。
- 状态栏小图标与「最近一次任务」常驻通知已复刻；算术题解锁、翻转感应、电源键暂停 / 贪睡、手动选贪睡时长、终止确认、执行界面静音态也都按原版复刻。原版的 TTS 语音播报、ROOT 操作、桌面小部件、硬件 MENU 键等未复刻，设置项按原版保留但只有与当前 Android 权限模型兼容的部分会实际生效。
- 原版普通版 5 个 / 增强版 10 个激活数量限制**已移除**，任意多条可同时启用。
- 铃声类型为「系统铃声」时，选「选择路径 → 系统铃声」会打开**系统铃声选择器**（`ACTION_RINGTONE_PICKER`，类型为闹钟），在 ColorOS 上就是原版那个「经典铃声 / 自然铃声 / 本地铃声 / 在线铃声」的页面；为「媒体库 / 指定音乐」时点选择路径直接列出媒体库音频；也可「从文件选择铃声…」或手动输入路径。选择路径行显示文件名。原版备份里的绝对路径在 Android 11+ 分区存储下不可读，导入后需要重新选一次。
- 模式 5「倒计时」为一次性提醒：「从现在开始=否」在目标日期的开始时间响一次；「从现在开始=是」从保存时刻起按「倒计时分钟」响一次（锚点存 `base[6]`，重启 / 重排程不重新计时）。原版的执行前等待倒计时（响铃前的等待提示）未复刻。
- 系统菜单在原版由硬件 MENU 键唤出；现代手机没有该按键，复刻版在标题栏右侧提供 `≡` 入口。

## 构建与 Release

```bash
./gradlew assembleRelease
```

`app/build.gradle.kts` 配置了 ABI splits，会产出三个 APK：

| 文件 | 架构 |
|---|---|
| `AddinTimerRevive-<版本>-arm64-v8a.apk` | 64 位 ARM（一加 13 用这个） |
| `AddinTimerRevive-<版本>-armeabi-v7a.apk` | 32 位 ARM |
| `AddinTimerRevive-<版本>-universal.apk` | 通用（模拟器 / x86） |

## 仓库结构与上游关系

本仓库 fork 自 `lentikr/Reminder`（一款纪念日 / 倒数日应用）。**3.7.3 起，上游那套业务代码已全部删除** —— AddinTimer 复刻层从未使用过它。一并移除的还有只服务于它的依赖（Hilt、Room 3、DataStore、Navigation 3、kotlinx.serialization、tyme4kt、SplashScreen、Material3 adaptive）、对应单元测试、Room schema、界面截图与文案资源。保留上游的仓库名 / 包名 / 启动图标，只是为了让已安装用户能继续覆盖升级。

现在仓库里只有一套代码：

```
app/src/main/
├── kotlin/com/lentikr/reminder/
│   ├── MainActivity.kt          唯一入口，直接加载 TimerApp
│   ├── ReminderApp.kt           Application，只装崩溃日志收集
│   └── timer/                   AddinTimer 复刻层
│       ├── AtkModel.kt          参数 / 规则模型、.atk 文本解析
│       ├── AtkEngine.kt         精确闹钟排程、贪睡 / 暂停 / 静音重响
│       ├── AtkAlarmService.kt   前台服务、翻转 / 电源键 / 解锁监听
│       ├── AtkReceivers.kt      触发广播与全屏执行界面
│       ├── AtkUi.kt / AtkEditUi.kt / AtkSkin.kt   界面与控件
│       ├── AtkStore.kt          SQLite（原版 timer / actlog 表）
│       └── AtkSort.kt / AtkSlide.kt   排序与滑块方向判定（纯函数）
└── java/cn/nnci/addintimer/     Occurrence / Rule / Lunar（原版调度逻辑，本地 Java 源码）
```

单元测试只覆盖上面这套代码（`app/src/test/kotlin/com/lentikr/reminder/timer/`）：参数与规则序列化、旧备份无损导入、下次触发计算、执行界面选项默认值、排序分组、滑块方向。构建与发布方式见上文「构建与 Release」。
